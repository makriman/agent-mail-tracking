# Review 2026-09-23 — Agent Mail Track

DRAFT. Awaiting founder. Do not merge.

Reviewed `main` at `dde365e` (Worker, D1, Node client, secrets, mint/send). [PR #6](https://github.com/makriman/agent-mail-tracking/pull/6) (`cursor/amt-mcp-bridge-292a`) was read only. It stays a founder-gated draft. This PR does not add `mcp/` and does not merge it.

No Critical or High issues on `main`. Auth fails closed, SQL is parameterized, open/click tokens are HMAC, and the tracked `<img>` survives quoted-printable in the existing MIME tests. The gaps below are Medium and Low. This PR hardens the ones that are small and behavior-preserving for real sends.

## Top findings

### Critical

None.

### High

None on `main`.

### Medium

1. **Valid open/click URLs are unauthenticated D1 writers, and dedupe still inserts.** `GET /o/:token` and `GET /c/:token` are public by design (mail clients). `recordEvent` in `src/db.ts` inserts an `events` row even when the one-hour dedupe matches, and only skips the counter update. A leaked pixel or click URL can fill D1. There is no rate limit on mint or on those routes. Not changed here: skipping the deduped insert would hide deduped rows the dashboard shows, and a real limit needs a durable counter. Follow-up, not a drive-by.

2. **Webhook SSRF.** `POST /v1/messages` stored any `https:` URL (and `http://localhost`). The first open or click, which is unauthenticated, `fetch`ed that URL and followed redirects, so a redirect could retarget the POST. Setting the URL still requires `API_KEY`. **Fixed in this PR:** `isAllowedWebhookUrl` allows public `https` plus `http` only for `localhost` / `127.0.0.1`, and rejects userinfo, loopback-on-https, RFC1918, link-local, CGNAT, metadata names, `.internal` / `.local`, and all IPv6 literals. `fireWebhook` uses `redirect: "error"`. Residual: DNS rebinding to a public name that later resolves private. Workers do not have a pinned-IP fetch helper here.

3. **Gmail raw could ship without the pixel.** SMTP sends `raw_mime`. Gmail sends `raw_base64url`. `mintTrackedMessage` only checked that both strings were non-empty, so a response whose base64url dropped `<img>` (or diverged from `raw_mime`) was still sent. Connector `htmlBody` was already rejected. **Fixed in this PR:** `assertSendableRawMime` requires the two fields to decode to the same bytes, and requires an `/o/` `<img>` unless `mode` is `plain_only`. Called from `mintTrackedMessage` and again in `sendTrackedEmail`. The MIME builder was not changed, so this does not strip images.

### Low

4. **Click `Location` was the stored string, with no cache headers.** `isSafeRedirectUrl` already rejected `javascript:`, `data:`, and protocol-relative URLs. It still allowed userinfo (`https://user@host`) and a raw string a non-WHATWG client could parse differently (`\`). `302` responses had no `Cache-Control`, so a cache could skip later click hits. **Fixed in this PR:** redirects use `canonicalRedirectHref` (parsed href, no userinfo, no control characters) and `no-store` / `CDN-Cache-Control: no-store` / `Referrer-Policy: no-referrer`. A bare origin such as `https://example.com` becomes `https://example.com/` in `Location`. Paths are unchanged. Pixel responses already sent `private, no-store` (Workers Cache bypasses those). `CDN-Cache-Control: no-store` was added. Gmail and Apple image proxies can still cache pixels; that is a client limit, not a missing header.

5. **Token compare was `===`, and token length was unbounded.** HMAC is SHA-256 truncated to 16 bytes (`src/tokens.ts`), bound to kind `o` or `c`, so this is not a practical forge. **Fixed in this PR:** compare goes through `safeEqual`, and tokens longer than 512 characters are rejected before HMAC. API key checks already used `safeEqual`.

6. **Single `API_KEY` is the whole authorization boundary.** Not IDOR. `GET /v1/messages` and `GET /v1/messages/:id` require the key (`app.use("/v1/*", requireApiKey)`). Message ids are `msg_` + 16 random bytes. Open/click handlers do not take a caller-supplied `message_id`; the id is inside the HMAC token. Anyone with the key can read every recipient, subject, metadata, and event user-agent. v0 is one tenant. Dashboard `GET /` and `GET /m/:id` use the same key. HTML is escaped (`escapeHtml`). **Fixed in this PR:** dashboard and `/v1/*` responses send `Cache-Control: private, no-store`. Dashboard CSP adds `frame-ancestors 'none'`.

7. **IP hash trusted `X-Forwarded-For` when `CF-Connecting-IP` was absent.** On Cloudflare the platform sets `CF-Connecting-IP`. **Fixed in this PR:** only `CF-Connecting-IP` is hashed. Spoofed forwarded headers no longer change dedupe keys.

8. **SMTP envelope and EHLO.** `envelopeAddress` rejected CR/LF only after extraction, so a newline plus `<other@evil>` could become the envelope recipient. Comma-addresses were allowed. EHLO used the caller string raw. **Fixed in this PR:** CR/LF fails closed before parsing; a single display-name `<addr>` is allowed; the addr-spec is one token without spaces or `<>"'`. EHLO strips CR/LF/whitespace. `Buffer.toString()` is called with no encoding argument (utf8 default) so Worker `tsc` accepts this Node file. AUTH PLAIN is base64, so the password cannot inject a second SMTP line.

9. **Secrets in git.** No live API key, SMTP password, or OAuth token. `.dev.vars` is gitignored. `.dev.vars.example` is `dev-api-key-change-me` / `dev-token-secret-change-me`. `docs/agent-send.md` uses `ya29.ACCESS_TOKEN_PLACEHOLDER`. `wrangler.jsonc` has D1 id `974c8d6d-aada-49d7-90d1-694d65621a12` (resource id, not a credential). Do not treat the example key as a production secret.

10. **Dashboard list status can disagree with the API.** `renderList` calls `messageStatus` without `hadHumanOpen`. The JSON list does query human opens. A later proxy hit can relabel the HTML list `proxy_open` while `GET /v1/messages` stays `high_confidence_open`. Not changed (query behavior, not a one-line guard).

11. **Workers config nits (not changed).** `compatibility_date` is `2026-09-11`. `nodejs_compat` is already the default for that date. Observability is on, without an explicit `head_sampling_rate`. `worker-configuration.d.ts` is a short hand-written `Env` (`DB`, `API_KEY`, `TOKEN_SECRET`) that matches the config. Bumping the compatibility date can change runtime defaults, so this review left it.

## Reviewed, not vulnerable

| Open redirect schemes | `javascript:`, `data:`, `mailto:`, `file:`, `ftp:`, `//host` rejected at mint (`shouldRewriteLink`) and again at click. |

| API key timing | `safeEqual` in `src/crypto.ts`. Empty `API_KEY` fails closed (`401`). |

## MCP draft (PR #6) — do not merge

Not on `main`. Founder-gated. Notes only:

- `send_tracked_email` can deliver caller-supplied `raw_mime` / `raw_base64url` without requiring `has_open_pixel`. The summary flag is advisory (`mcp/summary.ts`). A send-without-mint path can ship MIME that dropped the pixel.
- `htmlBody` / `textBody` are rejected in `mcp/args.ts` (`rejectBannedConnectorFields`). Schemas use passthrough so those keys are not advertised but still error.
- HTTP defaults to `127.0.0.1`. `0.0.0.0` without `AMT_MCP_HTTP_TOKEN` logs a warning and still listens. Bearer check is `===`, not constant-time. `/health` is unauthenticated.
- Mailbox secrets stay in the MCP process env, not Worker secrets. That split is right. Do not move SMTP or Gmail tokens onto the public Worker.

## Hardening in this PR

- `src/redirect.ts` — canonical click href; reject userinfo and control characters.
- `src/index.ts` — click `302` no-store; `/v1` no-store; `Content-Length` cap 512 KiB; CF-Connecting-IP only.
- `src/webhook.ts` — webhook host policy; `redirect: "error"`.
- `src/tokens.ts` — length cap and `safeEqual`.
- `src/pixel.ts`, `src/dashboard.ts` — no-store and frame-ancestors.
- `client/guard.ts`, `client/mint.ts`, `client/send.ts` — raw MIME equality and pixel guard. Does not remove `<img>`.
- `client/smtp.ts` — tighter envelope and EHLO.
- `AGENTS.md` — Cloud Agent build/test, Worker+D1, secrets, mint → SMTP / `gmail_raw` only.
